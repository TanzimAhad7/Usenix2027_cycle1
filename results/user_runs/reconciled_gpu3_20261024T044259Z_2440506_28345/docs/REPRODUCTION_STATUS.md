# Reproduction modes and source limits

The root launcher separates four evidence modes. All approved jobs use nohup, logs/status files and the project venv.

| Mode | Implemented command | Evidence |
|---|---|---|
| Delivered-file and inherited-byte integrity | `bash VERIFY_PROJECT.sh` plus inherited integrity inside historical audit | Selected files/bytes only; not original full-archive certification |
| Frozen reanalysis | `bash LAUNCH.sh historical historical_01` | 48 original scientific claim checks and corrected primitive source/N3/live/oracle calculations; no model calls |
| Frozen display regeneration | `bash LAUNCH.sh figures figures_01` | Figures 2–6 from inherited inputs; figure 1 copied because its original producer was not supplied |
| New component experiments | `bash LAUNCH.sh components components_01` | Source-bound native R/B scenarios with custom simulated tools and declared scripted actors |
| Adapted autonomous R/B development | `bash LAUNCH.sh models MODEL_RUN_ID 2` or `3` after actual deployment qualification | Model-generated actions under the included custom workflow; no authoring model episode completed |
| Full new H24/P, S128, A64/H64, reference forks or confirmation | No launcher claimed | Source/contract/implementation and scientific qualification still required |

## Historical source is preserved, not silently repaired

`research_basis/` contains the selected original code/data bytes. Its old README, GPU defaults and entrypoint names describe the rejected study's artifact. They are source evidence, not this project's operating instructions. Do not execute its old all-in-one GPU launchers. Use the current root launcher; only physical GPU 2/3 is permitted.

The plan identifies concrete unresolved defects in historical fresh-rerun infrastructure: stage 05 loopback URL mismatch, stage 09 restoring a 16K context instead of the accepted 32K capacity path, and fresh stages/figures restoring frozen parents. The old PAEF oracle also has a single-effect workload and semantic limits; replay uses historical agreement and a frozen continuation. These are preserved for diagnosis and have not been globally repaired. Inherited full-archive hash/source-coverage checks refer to the original full distribution, not this selected derivative.

The frozen-check adapter redirects inherited outputs into a new run directory in memory without changing scientific checks or original source bytes. It runs the eleven study/isolation verification functions and omits old whole-package source-coverage/hygiene certification. Several legacy checks inspect saved analysis/metadata; the new primitive report separately reconstructs corrected source-only versus quartet counts, N3 endpoint versus joint contrasts, all six live cells and oracle counterexamples. It does not independently relabel all historic effects or upgrade labels into validated authorization.

The figure worker uses the original stage-12 temporary compatibility view and explicitly reads frozen parents. Passing rendering/byte comparisons is display reproduction, not fresh evidence. New-paper displays must follow new raw run IDs when new claims are made.

## Environment scope

The root CPU lock installs the current tested native diagnostic and plotting tools. `research_basis/requirements*.txt` preserve the original reported environment for historical source interpretation; they are not installed automatically and do not qualify fresh GPU reruns. Current native runtime-module hashes are checked against the frozen snapshot. Current local-model transport deliberately differs from the described missing pilot release in roles, generation settings, prompts and workflow; see the native protocol and findings.

Original source files may reference historical aliases, author environment paths or missing superseded support. Their old compatibility materializer expects the complete original distribution. The current frozen-analysis/figure wrappers resolve the selected inputs locally; a new full fresh DAG requires explicit parent wiring and claim-specific tests before being offered as a supported command.
