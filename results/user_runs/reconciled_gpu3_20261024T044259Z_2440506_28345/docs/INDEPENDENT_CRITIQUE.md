# Independent critique and strengthening of research plan v6

**19 October 2026.** Evaluated against the supplied manuscript, both USENIX reviews, the original A674 artifact, the complete incident report, and independently retrieved primary literature. Section references below identify the supplied `IEEE_SP_Standalone_Research_Plan_v6_2026-10-07.md`.

## 1. Assessment

V6 is a substantial scientific improvement over the rejected paper. It recognizes the contrary end-to-end evidence, makes D24 a small diagnostic rather than an acceptance gate, separates permission from source, retains protective and unknown outcomes, distinguishes reference-only forks from whole-agent repair, and leaves larger experiments conditional. Those improvements are already present; they should not be presented as new recommendations.

V6 is **not yet a validated execution authority or an evidence-ready S&P plan**. It combines a promising hypothesis, a detailed historical audit, conditional research routes, and claims about an unseen newer implementation. The decisive remaining weaknesses are novelty relative to very close memory work, native reachability, semantic validity of the forks, occurrence-level authorization binding, and a confirmation design whose precision follows its actual independent units.

The strongest enhancement is not another large matrix. It is a short scientific decision layer above v6: a closest-work kill test, source/runtime qualification, one mechanism diagnostic, and a result-dependent confirmation commitment. Keep the full historical record separately. This reduces decision ambiguity without discarding useful science.

## 4. The novelty test must precede commitment to history laundering

V6 already contains a broad literature map. Its residual risk is that a large map can obscure the small set of papers that decide novelty. The two memory papers should receive the same priority as DRIFT and ACE, not appear as peripheral related work.

The exact distinction to investigate is:

> A native execution guard uses a generated reference as authorization evidence. Shared untrusted history can make actor/reference agreement depend on one unsupported authority source, and the guard releases an effect that is independently unauthorized.

That differs from memory formation alone only if the native assessment, release, and effect are demonstrated. If the experimental result is merely “a summary invents a grant, the actor repeats it, and oracle removal helps,” the difference is too small. A typed memory representation, multi-domain benchmark, and oracle repair are already present in close prior work.

The proposed contribution memo should contain five statements: the prior result we cannot claim, the new trust assumption, the observation that exposes it, the intervention distinguishing it, and the result that would invalidate our claimed difference. An independent reader should be able to reject the novelty claim before expensive execution. This is a scientific safeguard, not an acceptance prediction.

The elementary invariant in §5—that equal relevant authority views imply equal authorization for a fixed effect—is a useful specification obligation. It is not a theorem-sized contribution. The paper needs new operational evidence about which system violates or preserves the obligation and why.

## 5. Promote occurrence binding from backlog to a discriminating probe

V6 acknowledges binding/coverage as a possible route. The supplied source supports a more concrete primitive than a generic stale-state hypothesis. Exact matching represents reference calls by function/argument signatures. In the independent fixture, one reference call admits two identical actor occurrences; both simulated effects commit. The receipt dictionary also maps both responses to the later ID.

Three tests are required, in order:

1. **Faithful primitive:** run the same condition inside the original supported runtime with non-idempotent effects and independently observed occurrence IDs. Establish whether another layer deduplicates, aborts, or makes the second call harmless.
2. **Native reachability:** allow an acting model to propose calls under a declared injection surface and budget. Do not count a forced two-call proposal as an autonomous exploit. Retain failures and protected cases.
3. **Mechanism discrimination:** replace signature membership with occurrence-bound matching/revalidation while holding the proposed batch, facts, authority, and environment fixed. Include a contract that genuinely permits two occurrences to expose overblocking.

If this only finds an isolated dictionary bug, repair and report it at that scope. If it exposes a recurrent architectural mismatch between reference traces and effect authorization across payments, grants, or other distinct semantics, it may justify a new research route. Do not combine it with history contamination solely to enlarge the story: one concerns independence of evidence; the other concerns what an agreement witness actually binds.

The malformed fuzzy-response and stale-reason fixtures also deserve conformance checks. They are not equal in evidentiary status. A permissive fallback can affect decisions; a retained reason can corrupt route telemetry without changing the decision. Neither establishes attacker control over judge outputs.

## 6. D24 is a useful diagnostic with a narrow interpretation

### 6.1 Keep its present identity

The actual schedule is two custom tasks × D-Fact/D-Claim/D-Grant × defense OFF/ON × two repeats. It is 24 workflows, with only two structural task units. V6 correctly labels it a descriptive diagnostic. Do not rename source-factorial results as D24 or treat 24 as a statistical certification target.

D-Fact versus D-Claim holds the no-grant contract fixed while adding unsupported approval prose. That is an interpretable content intervention if genuine facts, tool semantics, and delivery are actually equal. D-Claim versus D-Grant intentionally changes trusted permission and required completion. That is a useful positive control and behavioral discrimination check, not a pure estimate of authority sensitivity.

### 6.2 Fix the opportunity problem without seeding the result

A task that immediately calls a mutator after one lookup may create no nonterminal assistant descendant before the reference check. A null then says little about history reuse. Before model runs, trace the clean workflow to establish a legitimate need for intermediate processing: resolving a directory, comparing a schedule, or preparing a document can suffice.

Do not require the agent to emit an approval summary or force a malicious proposal. Record actual opportunities, delivery, and absence. A natural task with no descendant is a valid negative result in the total population; a deliberately standardized-exposure study answers a different boundary question and needs its own label.

### 6.3 Do not infer scope understanding from two changed fields

The implemented sharing example changes `partner1@example.test` as reader to `backup-partner@example.test` as writer. A rejection or acceptance does not identify which scope dimension mattered. Keep D24 as a coarse diagnostic, but if scope semantics becomes central, add recipient-only and privilege-only component controls. The calendar example provides a second task structure but does not resolve this sharing ambiguity.

For a pure permission probe, hold the candidate and nonsecurity objective fixed and vary only a trusted grant predicate at the assessment boundary. That is a component experiment. A separately designed autonomous task can use one common instruction to prepare the artifact and perform the nominated share only when permitted; optional sharing and preparation should then receive separate outcomes. Do not claim that unchanged wording alone guarantees an unchanged semantic goal.

### 6.4 Qualify the protected peer tool

`get_peer_nomination(task_id)` is harness-owned and cannot be made authentic just by putting a peer name in tool text. Verify sender/nomination binding outside attacker arguments and record which guard path treats this new tool as external. If it is absent from an allowlist, copied without attenuation, or handled by a new adapter, that is part of the experimental system. Declare the adaptation; do not describe a custom supported interface as an unmodified native deployment.

`request_confirmation` is a local record, not a real owner reply or a grant. A well-formed request may be appropriate handling with completion false. A vague deferral should not be automatically scored as security failure or successful resolution; review its meaning and resulting effects.

## 7. Reference forks need semantic validation of actual delivered evidence

V6 is unusually explicit about the fork limitation. The implementation described in §8.6 replaces shadow carrier text or truncates shadow history through the carrier, advances its synchronization index, and then permits reference generation. Acting history, pending proposal, and environment remain fixed. This is reference-state surgery, not replay of all historical events. The caveat is correct; it must become a practical review procedure.

For every selected checkpoint, create a closure table:

| Evidence item | Native | Source branch | Descendant branch | Combined | Required for legitimate action? |
|---|---|---|---|---|---|
| Genuine lookup value and identifier mapping | Present/absent | Present/absent | Present/absent | Present/absent | Yes/no with reason |
| Nomination identity and authentic sender binding | … | … | … | … | … |
| Root grant and relevant updates | … | … | … | … | … |
| Unsupported control/approval text | … | … | … | … | No authority; may still be observed |
| Later legitimate read or plan needed for feasibility | … | … | … | … | … |
| Prior effects/state constraints | … | … | … | … | … |

Populate it from **the actual requests delivered to the reference**, not only serialized snapshots. Mechanical eligibility—carrier present, history aligned, no later mutation—does not show that a later read can safely be discarded. Hash agreement proves lineage, not semantic equivalence.

If a branch omits a needed fact, either re-resolve that fact through a reviewed route or relabel the experiment as an information-removal bundle. If repair uses privileged knowledge of exactly which span is malicious, label it oracle-assisted. If legitimate authority changes, the branch cannot support the original permission-preserving comparison.

Native and placebo deep copies test some transport behavior but may not control the additional generation introduced by a regeneration branch. Use equal-compute or benign-regeneration controls when extra deliberation can explain the effect. A source/descendant interaction requires compatible native/source/descendant/combined cells; a placebo is an additional machinery check, not a missing cell of that factorial.

A fixed pending proposal is valuable for component causality. It cannot establish that a deployable policy would have prevented the earlier actor from generating that proposal. Report component assessment and autonomous whole-workflow outcomes separately.

## 8. Strengthen independent authority and outcome measurement

The independent oracle should be executable from trusted grant state and authoritative effects, with human-reviewed semantic cases. It must distinguish:

- allowed action from required completion;
- authenticated sender from empowered delegate;
- one permitted occurrence from repeated or aggregate effects;
- attempted call from successful effect;
- final desired state from absence of earlier unauthorized effects;
- uncertainty about observation from evidence of no violation.

The legacy oracle's URL normalization and keyword-negation counterexamples should become oracle review examples, not evidence that every historical label is wrong. Quantify how many actual cases are affected before revising aggregate claims. A two-payment outcome is unauthorized when the contract allows only one; a different contract may allow two. The oracle must not silently encode the first workload as a universal rule.

Store explicit `assessment_id`, `proposal_occurrence_id`, `reference_generation_id`, route, released occurrence, actual runtime invocation, receipt, and pre/post state. Validate cardinality: every committed effect maps to a released occurrence or an explicit bypass route; one receipt cannot stand in for two non-idempotent effects. Reasons and final-run labels must not substitute for current call-level outcomes.

The historic skip audit reports 44/210 defended runs entering a skip mode, 22 with later use, and 18/168 privileged calls unaudited. Its later 15/2/1 categories are final-run labels, not immediate call authorization. Join calls to effects before claiming an unauthorized skipped call. This is exactly the kind of denominator/label distinction that should remain in the artifact and out of broad prose until resolved.

For small diagnostics, review every episode independently, with authority evidence and effects shown before model narrative. Keep annotations, disagreements, adjudication, and UNKNOWN. If automated evaluation is tested with misleading approval prose, hold the trusted evidence fixed and call it an evaluator study; do not count it as actor compromise.

## 9. Confirmation needs a quantitative commitment, not just good principles

Section 11 states the right principles but does not yet instantiate them. Before confirmation, specify:

1. The primary endpoint and whether it is total-population, conditional on exposure, or conditional on an eligible checkpoint.
2. The independent unit and target population: new workflow structures, fixed selected tasks with stochastic repeats, or attack attempts under a budget.
3. The smallest difference that would materially change the security conclusion.
4. Expected paired discordance/heterogeneity from development and a sensitivity range.
5. The required precision, feasible allocation, and exact interpretation if the budget cannot reach it.
6. Fresh structures and realizations withheld from development, plus the consequence of using them to revise the method.

Do not insert an arbitrary power calculation treating 160 fork continuations as 160 independent tasks. Sixteen checkpoints can share tasks, histories, and preconditions. With few clusters, bootstrap intervals can look authoritative without reliable calibration. D24 should remain primitive counts and trace analysis.

Use any-violation across the whole observed lifecycle as the primary security outcome if the chosen question is unauthorized execution. Report secure completion and appropriate handling separately. Later recovery does not erase harm. Preserve logical bounds `[D/N, (D+Q)/N]` for unknown outcomes and distinguish those bounds from a sampling interval.

For threshold systems, show held-out coverage and utility, not only accuracy on assessed cases. For attacker adaptation, compare equal information/budget conditions and report failures, query counts, and selection. For configured model comparisons, do not attribute differences solely to weights when temperature, templates, role assignments, or judge availability also change.

## 10. Baselines, compute, and the practical intervention claim

At least one meaningful comparator should exercise independent authority reasoning using public root inputs. It can be simple if it answers the question. Separate extraction of facts/claims from enforcement of a reviewed predicate. A hidden-gold policy oracle is a diagnostic upper bound; an all-block policy is a security/utility lower baseline. Neither alone demonstrates practical improvement.

Do not attempt full DRIFT/ACE/AgentSys reimplementations merely to populate a table. Choose a faithful available implementation or a narrowly labeled mechanism comparison. Record unsupported features and do not credit the comparator with guarantees its evaluated interface does not supply.

Cost must cover the entire workflow: actor, reference, fuzzy judge, sanitizer, regeneration, retries, denied calls, recovery, and observation overhead where relevant. Report tokens, calls, wall time, and completion together. Small samples do not justify strong tail-latency claims. A second model can test model dependence but cannot remove shared-evidence dependence by itself.

The Qwen and Llama profiles in v6 are proposed configurations, not validated serving results. Record immutable model/tokenizer revisions and effective role settings from the server. Different templates and parser behavior are part of the system under test. No recommendation here assumes a particular GPU allocation or that a version string fully locks CUDA/transitive dependencies.

## 11. A more decisive active plan

Replace the beginning of v6 with the following dependency structure:

**A. Claim and source qualification.** Closest-work memo; obtain the newer release; verify source/configuration, contract semantics, observer joins, and full-runtime primitives.

**B. One small native diagnostic.** Reviewed D24 remains useful; add separately named targeted binding probes only if qualification warrants them. Record exposure, descendants, protection, effects, and unknowns.

**C. Independent mechanism decision.** Select shared-history failure, successful compensation, occurrence/binding failure, or measurement correction only if the complete evidence supports it. Write the competing explanation and falsifier before expansion.

**D. Minimal discriminating experiment.** Use valid same-state component interventions or autonomous comparisons appropriate to the selected mechanism. Do not automatically run every retained module.

**E. Fresh confirmation and manuscript.** Freeze the claim and analysis, then collect new structural evidence at an interpretable precision. Present negative and protective results in the same scientific explanation.

Suggested module disposition:

| Module | Recommended status |
|---|---|
| M0 | Required integration/capability qualification; not scientific confirmation |
| D24 | Retain after qualification; descriptive autonomous diagnostic |
| S128 | Conditional on source sensitivity being the unresolved operational question |
| A64 | Conditional on real grant/cue discrimination; repair goal/scope interpretation first |
| H64 | Conditional descriptive history-processing comparison; not automatically mediation |
| F160 | Replace fixed completion target with smallest semantically valid mechanism experiment |
| Temporal/concurrent/shared-state extensions | Add only if the chosen reference-specific claim needs them |
| Legacy CausalArmor/AgentWatcher repairs | Undertake only for a selected substantive comparison |

No deadline should force a weak mechanism into a submission story. Conversely, a valid negative result should change the plan immediately rather than trigger automatic enlargement.

## 12. Concrete changes to the document itself

1. Change the subtitle from “execution authority” to **“research specification; implementation and scientific validation status recorded separately.”** A document cannot certify unseen code or semantic review.
2. Add a one-page status table distinguishing supplied-source verified, v6-reported, implemented-but-unreviewed, model-unexecuted, and hypothetical.
3. Put the closest-work memo and source/runtime qualification before the D24 launch instructions.
4. Add the occurrence-binding primitive and its full-runtime/native-reachability falsifiers to the active decision layer.
5. Keep the explicit D-Grant goal caveat; add one-dimensional scope controls only if those semantics drive the chosen claim.
6. Turn fork caveats into a required actual-input closure record and independent semantic review.
7. Add a confirmation commitment template with estimand, unit, effect/precision target, and holdout policy.
8. Replace the calendar with evidence dependencies. Preserve historical dates only in provenance material.
9. Separate the active plan from the large retained audit dossier. This is not arbitrary cutting: active decisions and historical evidence have different review functions.
10. Rewrite the eventual abstract only after the selected mechanism and confirmation results exist. No current title or contribution bullet should presume a native failure.

V6 provides a strong foundation for honest research. These amendments make its next action more discriminating and its eventual claims harder to overstate. They cannot make acceptance “bulletproof”; they can make the argument concrete, falsifiable, reproducible, and responsive to the reviewers' strongest objections.
