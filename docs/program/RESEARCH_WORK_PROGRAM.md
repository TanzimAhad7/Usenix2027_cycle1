**Stage 0 — preserve/verify:** verify all supplied bytes; expand original archive; inspect selected old claim paths. Historical `VERIFY.sh` verifies stored outputs, but some recorded claims are cross-checked against saved analyses rather than recomputed from raw data. The present study must correct those limitations when reusing a figure.

**Stage 1 — trusted security truth:** write and independently review explicit grants, principals, allowed effects, count limits, legal alternatives, state observation, and UNKNOWN closure. General oracle cannot be inferred from the simulated payment ledger. Complete the test battery in the research plan §5.1.

**Stage 2 — native source and decision fidelity:** verify original policy/hash, AgentDojo version/runtime, real input and error schema, unchanged logging, native current-route/assessment/dispatch/effect joins. Use the R/B component matrix and keep all protective cases. Compare original code to named patched variants, not unrecorded edits.

**Stage 3 — genuinely model-generated behavior:** qualify actual model endpoint, parser, tool calls, attenuation, judge, identity and logged costs. Run small autonomous R/B development diagnostics (not forced candidate batches); record every enrollment, exposure, missing precursor, failure, protection and effect. External control surfaces must match the declared threat model.

**Stage 4 — optional H/P diagnosis:** if needed implement and qualify H24 fixed-objective study separately from reported old D24, and test real descendant formation, actual reference consumption and the protective explanation. Do not assume missing pilot code exists. A64/H64/S128 are **conditional**; run only to settle a named unresolved scientific question.

**Stage 5 — select one contribution:** prepare source- and method-specific novelty memo against DRIFT, ACE, AuthMem-Bench, Endogenous Authorization Laundering, CausalArmor/AgentSentry, and any closer implementation. Select mechanism based on importance, causal evidence, novelty and transfer; report strong alternatives/protected cases.

**Stage 6 — causal test:** change only the hypothesized review/occurrence/history/protection mechanism at a valid checkpoint; preserve task facts, true grants and effect state. For an autonomous trajectory, downstream proposals can diverge; do not describe a reference-only fork as rewinding an entire agent. Track all fork eligibility and selection.

**Stage 7 — preregistered fresh confirmation:** freeze outcomes, workload population/units, falsifier, alternatives, structural holdouts, model/attacker budgets, UNKNOWN/missingness, confidence and stop rules before collecting confirmation. Do not treat repeated runs as new independent task structures.

**Stage 8 — manuscript & artifact:** original paper may supply methodological background but not copied text or unsupported renewed claims. Build one complete contract → exposure → proposal → reference/review → release → dispatch → committed effect → independent authorization label → recovery chain. Show protection alongside failures, enforce nearest work comparisons, version scope, usable legal work, full-workflow cost and exact regeneration commands.


## Actual current commands

Use root `LAUNCH.sh` for every setup/research job. `setup` creates the root `.venv`; `historical` recomputes frozen evidence and corrected primitives; `components` reruns native controlled diagnostics; `figures` generates historical displays with documented render differences; `protocols` checks the five proposed schedules. `models RUN_ID 2|3` runs an existing qualified local endpoint. All proposed schedules remain declarations, not implemented scientific studies.

No bulk historical ZIP, external project or earlier plan is needed. Historical entrypoints are source evidence, not current launch commands. The inherited full-model pipeline has known defects. See `docs/REPRODUCTION_STATUS.md` for exact limits.
