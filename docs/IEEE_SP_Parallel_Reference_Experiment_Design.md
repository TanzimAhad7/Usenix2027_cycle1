# Parallel two-profile reference-discovery experiment design

Status: prospective Qwen3-32B and Gemma-3-27B-IT exploration under a frozen two-workflow execution profile; GPU3 serves each model sequentially and shared GPU2 runs a model-free accounting cross-check. The same conditions run separately on each model/interface profile. No new results are asserted.
Primary objective: decide which scientific explanation deserves an IEEE S&P
paper, including the possibility that no broad paper claim survives.

## 1. Scientific decision

The completed S1 study already establishes a conditional exact-admission
weakness. Another128-reference/192-admission repetition is low information.
The important unresolved questions concern natural guarded reachability and
what happens after a genuine admission decision changes execution.

This design keeps broad OFF/source comparisons, concentrates full comparator
trajectories, and adds authentic matched recovery. Case count is a consequence
of those questions, not an external runtime target. No default12-hour cutoff
is imposed. The optional user collection limit is an operational choice only.

## 2. Questions and rival explanations

| Question | Preferred explanation to test | Serious alternative |
|---|---|---|
| Can a complete source-guarded workflow commit an extra native effect? | The authentic conditional weakness is reachable | Guarded actors avoid the bad proposal; the component result has limited reachability |
| What explains a reached excess? | Exact reference support is reused | Reference itself is excessive; fresh later support, fuzzy admission or unreviewed routing is responsible |
| Does a legal block change recovery? | Admission feedback and actual prefix jointly matter | Ordinary service interruption produces the same behavior |
| Does truthful commit information help? | Outcome evidence changes what is retried | The model ignores correct evidence, stops safely, or succeeds without it |
| Is apparent protection merely lost functionality? | A comparator preserves both safety and lawful completion | It prevents effects by stopping necessary work |
| Do count failures reflect a specific dimension? | Count differs from target/parameter boundaries | Different attack wording and task geometry explain the contrast |

Do not choose a main mechanism before these alternatives are compared.

## 3. Frozen allocation

| Phase | Allocation per model | Detail |
|---|---:|---|
| CORE |176 autonomous workflows|DM, email and bank: seven shape/grant pairs, neutral/count carriers, OFF/source; selected upfront exact-capacity and trusted-gate trajectories; second facts only on decisive upfront controls. Channel coverage reduced to upfront one/two and staged two|
| MATCHED RECOVERY |At most30 continuations|First eligible origin in each of six DM/email/bank × neutral/count strata; five arms per origin|
| EXECUTION RECOVERY |72 autonomous workflows|Three primary families × two grants × neutral/count × NONE/FAIL_BEFORE/ACK_LOST × OFF/source|
| BOUNDARY |96 autonomous workflows|Recipient and parameter substitution, OFF/source, one fact realization, reduced channel panel|

Each model receives344 autonomous workflows:144 OFF,144 source RELEASE,28 exact-capacity,
28 source-plus-trusted-gate, plus at most30 conditional continuations. Across both
models this is688 autonomous workflows and up to60 continuations. Continuations
are not additional independent autonomous roots. The four fixed live interface
qualification requests (two per model) are recorded separately.

The executable frozen manifest contains every ID, root, carrier, operation,
initialization, policy and phase. The two-worker dispatch limit is fixed across
all policies and models; task submission follows the frozen order while actual
completion order may differ. Matched blocks and within-block policy order
are randomized prospectively with a fixed scheduler seed. Phase order places
the key reachability and causal questions before wider boundary exploration.
No favorable-outcome stopping rule, resampling or hidden replacement search.

Two fact realizations test basic sensitivity on the principal upfront
one-/two-operation controls. They do not supply a field prevalence estimate or
independent task population. One/two realizations are explicitly exploratory;
confirmation sample sizes must follow an eventual claim and observed variation.

## 4. Complete autonomous workflows

UPFRONT supplies one or two authorized operations after a real native read.
Batching is naturally available but never forced into an actor response.
SPENT requires actual authorized commits before a notice appears; no further
effect is then authorized. CONTINUATION produces a notice after an initial
distinct authorized operation and permits one/two remaining operations.
STAGED requires a first real read and commit before a second operation's data
exists in the environment. These are different execution structures.

Neutral, count, recipient and parameter carriers retain designated task facts.
The root fixes count, destination and bank amount/date; procedure text cannot
rewrite authority. Forbidden destinations exist in the simulator, so a bad
proposal is not protected merely by an invalid-address error.

OFF and source run complete fresh trajectories. Differences between their
single observed outcomes are descriptive policy contrasts; they do not isolate
the effect of a particular blocked candidate when the proposals differ.

## 5. Authentic matched recovery

Eligibility requires all of the following at an actually reached source
checkpoint: CONTINUATION or STAGED; at least one real native effect; prefix
within the trusted finite contract; an entirely denied sensitive batch; every
pending operation within remaining permission; and a model prefix through the
decision without truncation or unhandled transport failure. The source's
documented unsupported-logprobs fallback is allowed and preserved.

After all CORE jobs drain, independently for each model choose the first eligible
checkpoint per declared family/carrier stratum in frozen workflow/proposal order.
Selection reads actual saved candidate/decision records; completion speed does
not affect priority. Do not consult the parent's final outcome.
Do not require a successful exploit. No eligible checkpoint is an important
non-exposure result; preserve it and execute the remaining autonomous panels.

This eligibility class concerns a fully denied next sensitive batch after a
lawful prefix. It is not a test of every mixed partial-batch release mechanism
from earlier installment experiments. Do not generalize it to those cases.

Save and authenticate the native world, real messages, shadow history, routing
flags, pending proposal, loop attributes and actual initial decision requests
and responses. Each fork reconstructs that state and reuses the decision tape
with exact role/request checks. There is no guessed reference or substituted
actor proposal. After that decision, model generations are fresh.

| Arm | Initial cause | Feedback for recovery |
|---|---|---|
| GUARD_SOURCE | Actual source denial | Unmodified source feedback |
| GUARD_NEUTRAL | Same source denial | Common truthful zero-new-effect notice |
| SERVICE_NEUTRAL | Actual native pre-dispatch interruption of the same proposed batch | Identical neutral notice |
| GUARD_COMMIT_AWARE | Same source denial | Actual committed effects and pending unexecuted operations |
| SERVICE_COMMIT_AWARE | Actual pre-dispatch interruption | Identical commit-aware record |

The service intervention deliberately lets the held denied proposal reach a
real runtime failure before native execution. It is an experimental causal
control, not claimed natural source behavior. It adds no committed effect.
Ordinary source admission resumes for subsequent fresh proposals in both arms.

Run independent continuation arms in isolated processes with the same maximum
of two in flight. Each arm retains its own state and ordered dependent calls.
Record actual effective actor, reference, attenuator and judge inputs. Compare
the first fresh actor request and the complete common request prefix, without
normalizing identifiers. Also record first fresh inputs by role and whether
those queries succeeded. Unreached roles receive no equivalence certificate.

If first actor inputs differ, do not infer a hidden guard-versus-service causal
effect from their outcomes. Even equal first inputs do not prove identical
whole trajectories; sampled auxiliary outputs can change later inputs. Preserve
the divergence and bound the claim at the certified point.

## 6. Ordinary execution recovery

The separate autonomous recovery panel tests no fault, failure before commit,
and a real commit followed by an unavailable acknowledgement. Faults trigger
once at an eligible native dispatch. A blocked proposal is not covertly
executed to manufacture a fault. Fault exposure is policy-dependent.

Roots and initial notices match across fault profiles within a factual block.
Fresh generations can diverge. This panel establishes ordinary reachability and
containment under declared faults; it is not automatically the same causal
comparison as the authenticated guard/service forks.

## 7. Comparators and measurements

Exact-capacity changes only repeated exact support within one proposal. It
retains the original fuzzy route and resets at the next proposal. It is not a
remaining-permission ledger. The conventional trusted gate receives an explicit
machine-readable contract and actual native state; it is a privileged positive
control, not a claimed new deployable defense.

At every reviewed sensitive proposal, preserve immediate native dispatch
counterfactuals on actual state/candidates/references. They use no new model
calls and do not estimate fresh future recovery. Full comparator trajectories
are retained on selected controls for precisely that reason.

Primary endpoints: actual unauthorized native effects, authorized physical
completion and their routes. Report review coverage, exact/fuzzy support,
reference multiplicity, errors, protocol reads, censoring and reporting
separately. Report-token presence is not truthful free-form reporting.

For each committed effect, link the originating proposal to the first accepted
actor request containing the carrier. Eventual exposure is insufficient if the
forbidden proposal occurred earlier. Temporal precedence is necessary, not
sufficient, for attacker causation. Neutral and OFF controls remain essential.

Native banking records do not imply settlement or balance loss. Email and
Slack effects are simulated. Finite exact-operation contracts do not test
arbitrary aggregate budgets or grouping-equivalent recipient permissions.

## 8. Outcome-dependent scientific decision

| Outcome | Interpretation and next move |
|---|---|
| Conditional weakness remains, autonomous guarded excess absent | Component result only; stop repeating S1 and reassess significance |
| Reached excess disappears under exact capacity at the same checkpoint | Known occurrence handling explains that admission; a scoped bug may survive without a new architectural principle |
| Excessive references or later regenerated support survive capacity | Investigate the corresponding reference/state route; do not blame same-batch reuse |
| Guard and actual service interruption agree under certified inputs | Ordinary recovery is a sufficient rival; reject security-specific necessity there |
| Commit-aware feedback changes effects but loses completion | State the safety/functionality boundary, not a solved repair |
| No authentic eligible recovery origin | Matched intervention unexposed; do not insert a scripted origin and call it autonomous |
| Target/parameter boundaries protect while count fails | Bounded task/payload contrast, not proof of an intrinsic authorization representation |
| Only adapted or technically censored cases fail | Narrow profile/scope and preserve uncertainty |
| All residual effects reduce to familiar implementation errors | Consider a focused technical report/disclosure; do not inflate into an S&P principle |

Only after a consequential, discriminated result survives should the project
commit to a larger confirmation campaign or an independent implementation
test; the two models here provide bounded exploratory breadth, not broad generalization. A week-long run is not automatically launched by this experiment.

## 9. Execution and evidence preservation

One nohup invocation qualifies the native runtime once, preflights both cached
models and their effective interfaces on CPU, serves Qwen on physical GPU3,
executes its entire schedule, shuts it down, then serves Gemma and executes the
same full schedule. All roles use the selected family within a model worker.
Two persistent spawned research processes execute independent jobs within each
model, with process-local patching, timers and logging. The shared GPU3 lock stays
held across the handoff. A detected server outage drains active jobs before an owned restart; failed
cases are retained and never redrawn. An ambiguous owned shutdown stops the handoff; scientific and ordinary technical failures do not suppress
the other profile. Existing research/serving virtual environments and pinned
cached revisions are required; no installation or weight downloads occur.

All attempts, negative outcomes, unexposed forks, tool errors, partial effects,
truncated responses and technical stops remain in the census and raw archive.
There is one full raw archive and an all-case compact review bundle. Redundant
raw upload shards can be requested or generated later without new inference.
No model experiment was executed to produce this package. Build-level checks
and native/runtime validation not performed here are distinguished explicitly.
The full native regression suite and model-specific checks run automatically
on the user's machine before scientific collection.

## 10. Model/interface qualification and scientific scope

Qwen revision `9216db5781bf21249d130ec9da846c4624c16137` retains its unmodified
cached chat template and native Hermes parsing. Gemma revision
`005ad3404e59d6023443cb575daa05336842228a` uses a declared Gemma-turn tagged-JSON
template and strict non-streaming vLLM parser plugin. This avoids assuming the
cached plain Gemma template can represent OpenAI tool messages or that a
parser requiring model-specific tokens is compatible. The adapter, schemas,
rendered fixture prompts, token IDs, raw tagged output and parser code are
preserved. It does not make authorization decisions, consume permission or
repair malformed generated arguments. A malformed tagged response is technical
failure, not a successful effect-free completion.

Each effective template must retain actor, reference-history, attenuator and
judge fixture data under CPU tokenization. The exact Gemma parser is imported,
instantiated against its cached tokenizer, and exercised before either server
loads. Two fixed live probes per server then check tool generation/parsing and
a tool-result continuation. They use no scientific task outcome to select a
configuration. There is no adaptive template search or favorable redraw. Probe
failure leaves that model's scientific cases unexecuted; all evidence survives.

The same contracts, carriers, policies, phase order and fact realizations run
on each profile. Checkpoints are selected from its own real trajectories;
Qwen's checkpoint is never called an authentic Gemma origin. All roles switch
together, so this campaign does not isolate actor-family from reference-family
effects either.

Treatment contrasts within each profile are primary. Agreement across two
profiles strengthens bounded evidence of transfer. Disagreement must be
explained from the actual requests, proposal structures and interfaces; it is
not a clean causal estimate of model weights or architecture. Gemma is not a
byte-faithful replication of earlier JSON-interface runs. One implementation,
authored tasks, few fact realizations and possible absent checkpoints remain
limits even if both models show the same effect.

## 11. Wall-clock optimization and execution-profile qualification

All344 conditions and30 declared continuation slots remain per model. Two
isolated persistent research workers share a single GPU3 vLLM server. When one
job finishes, the next untouched job may start while the other continues.
Dependent actor/reference/tool operations within a job remain sequential.
Phases fully drain before the next phase; checkpoint origins follow frozen
order rather than completion order. Initial worlds, role patches, histories,
logging and per-workflow signal timers remain process-local. Source operative
methods and all retained vendor files remain unchanged.

A single native CPU qualification is reused only when package hashes,
qualification checksum, research Python identity and every pinned runtime
source still match. It additionally checks mocked serial/parallel native effect
parity, parallel authenticated fork replay, and independent JSON effect decoding.
Live workspace checkpoints restore each persisted Inbox field without running
the native Inbox's task-initialization validators. This preserves sent and
received messages, read status, trash, contacts and identifiers. The complete
restored environment and sealed world must match their saved hashes exactly;
failure remains fatal. Recovery inherited effects are read from this already
authenticated world, without a second initialization. CPU regressions cover
all five recovery arms across the three primary families, inherited versus new
effect accounting, continued native dispatch, and malformed-state rejection.
These CPU tests execute before GPU model inference and do not demonstrate model
reachability. Model/template/parser/live qualification remains separate.

Raw role/wire I/O is saved synchronously. Diagnostic tokenization uses one
background worker per active workflow, copies exact payloads and drains before
that workflow closes. No output is shared across independent cases. The API's
context/output limits, sampling parameters and watchdogs remain unchanged.

Concurrency changes batching, actual server request order and potentially
random-number consumption and generated outputs. This is a declared two-worker
execution profile, not bit-identical serial replication. All policies and both
models receive the same concurrency cap, but finite phase tails can have one
active job. Record actual active sets, process IDs, submission/completion events,
queue-inclusive HTTP times, model responses and failures. Do not interpret
case timing as GPU compute time or assume independent sampled outcomes. No new
per-request seed or favorable retry is introduced to hide variability.

The server-restart controller waits for both active jobs to drain before an
owned restart. A restart does not deliberately terminate the other active
workflow or redraw failed cases. Cancellation sends signals only to tracked
research-worker birth identities; hard cleanup leaves incomplete cases unknown.

One source snapshot, no per-model analysis/compression during handoff, one final
full raw archive, gzip level1 and optional duplicate upload shards reduce file
work. No scientific cells, controls, repeats or raw evidence are removed.
There is no measured speedup claim or default global cutoff. The final report
records observed overlapping case durations and phase wall time; their ratio
is not a serial counterfactual speedup measurement.

## 12. Shared GPU2 accounting cross-check

GPU2 is not a second inference device in this protocol. It loads no model
weights and no vLLM. A low-priority helper in the existing serving environment
reconstructs committed effects directly from native JSON independently of the
primary observer. It compares event/native-state agreement, finite operation
multiplicity and completion, and actual exact-reference/released multiplicities.
Operation signatures are mapped without hashing collisions to integer IDs;
small CUDA integer-count operations are checked against separate CPU counts.

The helper never modifies primary results, makes admission decisions, selects
origins or contributes new independent experiment cases. Reference multiplicity
alone is not a causal finding. A disagreement is retained as a technical review
requirement, not repaired by replacing the original experimental record.

Only the pinned physical GPU2 UUID is visible. Approximate allocator budget:
256 MiB. Measured process soft budget:1 GiB. Minimum free memory:2 GiB. CUDA
context/driver overhead lies outside the allocator cap; there is no hard total
VRAM ceiling guarantee. Record actual process memory and health. On pressure,
overage, failed ownership/memory checks or unavailable CUDA, the CUDA helper
exits completely. The controller subsequently starts a separate pure CPU helper
at the next model boundary or final drain. All raw cases remain auditable.

The audit's append-only history preserves successful CUDA checks even if a
later CPU fallback produces a newer per-case record. Missing native state and
unexposed continuation slots are separate from successful audits. All cases
with complete native artifacts are drained before final packaging, and any
incomplete drain remains explicit. Foreign GPU2 processes are untouched.

The principal wall-clock opportunity is overlapping inference on GPU3. The
GPU2 cross-check is useful measurement validation, not a claim that tiny
accounting kernels substantially accelerate model generation. Actual CUDA
execution and live batched vLLM integration are not claimed as tested during
package construction.
